# Raajply ERP — Architecture (prototype v0.3)

Prototype of an inventory, production, sales and finance system for a wood manufacturing company
(logs in → sawmill / plywood unit → finished goods → distributors → invoices and payments).
Runs on demo data. Built with **zero external dependencies**: plain Node.js on the server and
plain HTML/CSS/JavaScript modules in the browser, so it runs anywhere with `node server/server.js`.

## 1. High-level

```
 Browser (laptop / phone)
   └─ Single-page app  (public/)         hash router, role-based menus, SVG charts & icons
         │  fetch JSON + Bearer token
         ▼
 Node.js HTTP server (server/server.js)
   ├─ Static file server (public/)
   ├─ Router  (/api/...)                 permission check on every route
   ├─ Auth    (scrypt passwords, HMAC-signed tokens, 12h expiry)
   ├─ Route modules                       auth · dashboard · reports · masters · yard · production ·
   │                                      inventory · approvals · sales · dispatch · finance · admin · search
   ├─ Hardening                           CSP + security headers, gzip, login throttling, startup backups
   ├─ Services
   │    ├─ stock.js     append-only stock ledger → balances, reservations, valuation
   │    ├─ finance.js   FIFO receipt allocation, ageing, party ledgers, GST, cash/bank books
   │    └─ audit.js     who / when / what / before → after for every change
   └─ Store (server/db.js)               JSON document store, atomic write (tmp + rename)
         ▼
 data/db.json   (generated by server/seed.js — 6 months of realistic demo data)
```

## 2. Core rules

1. **Stock is never typed in.** Every movement is a row in `stockLedger`
   (GRN, ISSUE, PROD_OUT, BYPRODUCT, DISPATCH, TRANSFER_OUT/IN, ADJUST). Balance = sum of rows.
   Rows are never edited or deleted; corrections are new rows (adjustments need approval).
2. **Everything is audited.** Every create / update / approve / login writes to `audit`.
3. **Role-based access.** 12 roles; each API route declares the permission it needs.
4. **Approvals built in.** Stock adjustments, credit-limit overrides, large supplier payments.
5. **Indian specifics.** CFT (Hoppus rule for round logs, L×W×T for sawn), sheets for plywood,
   GST per HSN with CGST+SGST (intra-state) or IGST (inter-state), e-invoice IRN and e-way bill
   fields (mock values in the prototype), forest transit pass on each inward load.

## 3. Data model (collections in db.json)

| Collection | Key fields |
| --- | --- |
| company, locations, species | company profile & GSTIN; yards, plants, godowns; wood species with rates |
| products | sku, category (Sawn timber / Door frames / Plywood / By-product), species, unit, rate, HSN, GST %, reorder level |
| suppliers, distributors | party masters; distributors carry credit limit, credit days, discount, sales executive |
| users | name, username, role, scrypt hash, active |
| gateEntries, logs | inward truck: supplier, vehicle, transit pass, species, rate; each log: tag, girth, length, CFT, status |
| purchaseBills, supplierPayments | auto-created bill per gate entry; payments against bills |
| workOrders | plant, species, logs issued, input CFT, outputs, by-products, recovery %, status |
| stockLedger | ts, type, itemType (log / product), itemId, qty (±), unit, location, ref |
| orders, dispatches, invoices | sales order → approval → dispatch (vehicle, e-way bill) → GST invoice (IRN) |
| receipts, expenses | money in from distributors; operating expenses (cash / bank) |
| approvals, audit, counters | approval queue; audit trail; document number sequences |

## 4. Frontend structure (public/)

```
index.html          app shell
css/app.css         design system v2: zinc neutrals, indigo accent, Geist type, inset panel layout, print styles
js/app.js           boot, auth state, sidebar + topbar, hash router, ⌘K command palette, quick-create menu
js/api.js           fetch wrapper (token, errors)
js/ui.js            html templating with auto-escaping, data table (search/sort/paging/CSV),
                    modal, toast, tabs, formatters (₹ lakh/crore, dates, CFT)
js/icons.js         inline SVG icon set
js/charts.js        SVG bar, grouped bar, line, donut, horizontal bar charts
js/art.js           generated wood-grain textures for species & product thumbnails
js/pages/*.js       one module per screen
img/                logo, login illustration
```

Screens: Login · Dashboard · Log Yard (gate entry with live CFT calculator, log tags) ·
Production (work orders, output, recovery) · Inventory (stock, ledger, transfers, adjustments) ·
Sales orders (credit check) · Distributors (profile, ledger, ageing) · Dispatch (loading slip,
e-way bill, invoice) · Finance (overview, invoices, receipts, purchase bills, expenses,
cash book, bank book, GST) · Masters · Approvals · Admin (users, roles matrix, audit log, settings).

## 5. Path to production (after prototype approval)

- Swap the JSON store for PostgreSQL (same collections → tables; ledger and audit as append-only tables).
- Move the frontend to Next.js + TypeScript if the team prefers, keeping the same API.
- Real e-invoice / e-way bill through a GST Suvidha Provider; Tally export; WhatsApp/SMS alerts.
- Hosting: managed Postgres + Node server, daily backups, HTTPS.
